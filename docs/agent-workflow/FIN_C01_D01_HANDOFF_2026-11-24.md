## Transaction boundary and sequencing
1. C01/D01 must be reviewed together: implement server-owned source-linked draft creation and independent authorized finalization before switching sale/purchase adapters. Do not ship a partial permission change that makes legitimate draft creation unusable.
2. Preserve existing organization/company/year authorization, current revisions and ledger rules; explicit current approval authority at finalization, server-derived actor, fail-closed access checks on all supported mutation paths. No new trusted client identity or revision fallback.
3. Source + linked voucher + balanced lines/dimensions + audit + reference reservation commit or roll back as a unit. Ordinary save never allocates final number or posts. Corrective draft is not finalized by editing.
4. Stable operation identity across retries; distinguish verified outcome and pending refresh. Preserve B01–B03 protections. Draft deletion, numbering and history require their own reviewed dependencies; no migration of existing posted history in this package.
5. Before any SQL change, inventory effective function definitions and grants in exact candidate; use disposable local DB and collision-free migration from CLI. Review rollback and preserve existing tests. No hosted migration.
