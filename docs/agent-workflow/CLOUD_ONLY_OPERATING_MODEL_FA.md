# مدل اجرایی Cloud-only و همکاری عامل‌ها

تاریخ تصمیم مالک: ۲۰۲۶-۱۱-۱۵

## تصمیم قطعی

تمام عملیات توسعه، آزمون، یکپارچه‌سازی و انتشار FactorEasyPro فقط در محیط آنلاین و از طریق GitHub انجام می‌شود.

- Remote Desktop Commander ممنوع است.
- PC مالک، فایل‌سیستم محلی، ترمینال محلی و اجرای محلی خارج از محدوده‌اند.
- مخزن GitHub مرجع یگانهٔ کد، شاخه‌ها، PRها، تصمیم‌ها و شواهد است.
- build و test فقط در GitHub Actions یا runner ابریِ مجاز انجام می‌شود.
- runner خودمیزبان روی PC مالک مجاز نیست.

## واقعیت مهم دربارهٔ موازی‌سازی

GitHub Actions می‌تواند jobها و workflowها را موازی اجرا کند؛ این قابلیت به‌تنهایی سه عامل هوش مصنوعی مستقل ایجاد نمی‌کند.

A/B/C فقط زمانی عامل‌های مستقل و خودکار محسوب می‌شوند که هرکدام runtime مستقل، مجوز محدود، دریافت مأموریت از GitHub، تحویل branch/PR یا artifact و گزارش قابل ممیزی داشته باشند. نام‌گذاری سه job به A/B/C یا اجرای سه تست موازی اثبات وجود سه عامل LLM نیست.

وضعیت فعلی:
- عملیات GitHub Cloud از این محیط قابل انجام است.
- workflow کیفیت موجود است و آزمون‌های syntax، preflight تبدیل، PostgreSQL ایزوله، invariants حسابداری و Playwright را اجرا می‌کند.
- سه عامل مستقل LLM با اجرای خودکار end-to-end هنوز راه‌اندازی و اثبات نشده‌اند.
- دسترسی و dispatch خودکار چت‌های جداگانه ChatGPT فرض نمی‌شود.

## الگوی تحویل

- `main` شاخهٔ مرجع و انتشار است؛ هر مأموریت شناسه، SHA مبنا، محدودهٔ فایل و معیار پذیرش دارد.
- هر جریان کاری branch اختصاصی دارد؛ تغییر مستقیم روی `main` ممنوع است.
- خروجی از طریق PR تحویل می‌شود.
- گزارش تحویل شامل SHA، فایل‌های تغییرکرده، آزمون‌های واقعاً اجراشده، CI، محدودیت‌ها و ریسک‌های باز است.
- فقط مدیر مرکزی وضعیت نهایی را در `PROJECT_STATE.md` و `docs/EXECUTION_STATUS.md` ثبت می‌کند.

## گیت‌های Merge و Release

1. تطبیق محدوده و SHA مبنا.
2. بررسی diff و تغییرات ناخواسته.
3. اجرای آزمون‌های هدفمند و CI لازم.
4. کنترل امنیت، tenant isolation، مجوز و عدم نشت داده.
5. برای تغییر مالی: توازن، idempotency، atomicity، rollback، concurrency، شماره‌گذاری و حفظ تاریخچه.
6. برای مهاجرت: پیش‌بررسی read-only، شمارش و جمع کنترل، dry-run، توقف امن و ممیزی.
7. تطبیق SHA نسخهٔ ساخته‌شده/منتشرشده با SHA مورد انتظار.
8. پس از عبور از گیت‌ها، Merge و انتشار خودکار فقط در محدودهٔ مجوزهای قبلی مالک مجاز است. این اختیار شامل تغییر secrets/permissions، هزینهٔ جدید یا عملیات مخرب خارج از دامنه نیست.

## امنیت Cloud

- secret، token، service-role key، credential، cookie، dump مشتری یا دادهٔ حساس در issue، log، artifact یا مستندات قرار نگیرد.
- secrets فقط در GitHub Actions Secrets/Environments با حداقل دسترسی استفاده شوند.
- فقط GitHub-hosted runner یا runner ابری تأییدشده؛ runner شخصی مالک ممنوع.
- workflowها با حداقل permissions و انتشار محدود به ref/environment مجاز اجرا شوند.
- artifactها محتوای غیرحساس و عمر محدود داشته باشند.
