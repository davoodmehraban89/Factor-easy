# مأموریت A01 — اصلاح محدود دکمهٔ گزارش باگ

متن زیر را به چت «فینورا — پیاده‌سازی رابط» بده؛ فایل‌های پوشهٔ `source` بسته ضمیمه‌اند.

```text
تو عامل پیاده‌سازی رابط فینورا هستی. مدیر پروژه و مرجع تأیید نهایی چت اصلی Codex است. فقط FE-A01 را انجام بده.

مخزن: davoodmehraban89/Factor-easy
مبنای دقیق: 155ee8919012eff73b4a0eacc7f1912a8b2b6203
ابتدا AGENTS.md، PROJECT_STATE.md و این مأموریت را بخوان. این مأموریت تقسیم کار مدیر است: گزارش تغییر را جدا بده، فایل وضعیت مرکزی را ویرایش نکن؛ مدیر آن را به‌روز می‌کند.

ایراد تأییدشده: در تنظیمات ← درباره، دکمهٔ «گزارش باگ» در index.html فقط alert('پشتیبانی فعال است.') اجرا می‌کند. همین صفحه مسیر واقعی پشتیبانی واتس‌اپ دارد. بررسی آپدیت کار دیگری است؛ به آن دست نزن.

نتیجهٔ لازم: کلیک گزارش باگ، مسیر موجود پشتیبانی را با متن عمومیِ قابل‌ویرایشِ گزارش مشکل باز کند. فقط پیش‌نویس؛ ارسال پیام خودکار نباشد. متن نباید نام مشتری/کاربر، ایمیل، اطلاعات مالی، وضعیت حساب، آدرس دارای توکن یا storage را بخواند یا ضمیمه کند. شمارهٔ تازه نساز؛ همان مقصد پشتیبانی موجود در همین فایل را استفاده کن. استفاده از لینک استاندارد با target=_blank و rel=noopener مجاز است؛ بازطراحی UI یا وابستگی تازه لازم نیست. برچسب طوری باشد که بازشدن واتس‌اپ روشن باشد.

محدودهٔ تغییر: فقط کنترل «گزارش باگ» در index.html و تست مستقل scripts/about-support.spec.js. تنظیمات CI، بقیهٔ دکمه‌ها، loader، هسته/محاسبات مالی، SQL، Auth و مجوزها ممنوع. قبل از تغییر، بررسی کن همین اصلاح در نسخهٔ کار تو قبلاً انجام نشده باشد؛ در آن صورت یافته بده، دوباره اجرا نکن.

پذیرش:
1) کنترل واقعی از مسیر تنظیمات/درباره قابل استفاده باشد؛ پیام موفقیت جعلی ندهد.
2) مقصد و متن عمومی درست باشند؛ لینک بدون کلیک کاربر باز نشود.
3) آزمون با رهگیری درخواست خروجی در محیط محلی باشد؛ هیچ پیام واقعی ارسال یا حساب واقعی تغییر نکند.
4) رفتار در منبع و خروجی build-pages با CSP فعلی سازگار باشد؛ CSP را ضعیف نکن.
5) کنترل با صفحه‌کلید قابل فعال‌سازی و در موبایل قابل مشاهده باشد.

اگر اجرای کد داری، branch/worktree جدا از commit مبنا بساز، آزمون شکست‌خوردهٔ مرتبط را قبل از اصلاح نشان بده، سپس اصلاح و تست هدفمند. قالب مرورگر موجود scripts/workspace-access.spec.js را بخوان. برای اجرای واقعی تمام پروژه را در همان commit checkout کن؛ بستهٔ ضمیمه فقط فایل‌های لازم برای بررسی است، برنامهٔ کامل قابل اجرا نیست.
اگر فقط چت و فایل داری، unified diff و تست پیشنهادی بده و صریح بنویس اجرا نشده. فایل بزرگ index.html را کامل بازتولید نکن. نبود ابزار اجرا را با ادعای PASS جبران نکن.

merge، push به main، deploy، نصب سرویس پولی و کار با دادهٔ واقعی مجاز نیست. خروجی با RETURN_TEMPLATE_FA.md و شناسه FE-A01 تحویل شود. در پایان منتظر بررسی مدیر بمان؛ خودت مأموریت بعدی انتخاب نکن.
```
