# وضعیت تبدیل اسناد به موقت — ۲۰۲۶-۱۱-۱۳

**هدف:** همهٔ اسناد مؤثر کاربران و شرکت‌ها برای بررسی و قطعی‌سازی توسط مالک به چرخهٔ موقت برگردند؛ اسناد جدید نیز ابتدا موقت باشند. **تبدیل واقعی هنوز انجام نشده است.**

مالک صریحاً پیش‌شرط بکاپ بیرونی را برای این عملیات کنار گذاشت. اتصال دوباره درخواست نمی‌شود؛ هیچ بکاپ یا بازیابی انجام‌شده‌ای ادعا نمی‌شود. تصمیم مالک دربارهٔ شرکت صحیح فاکتورِ دارای مغایرت نیز دریافت و ثبت شد. اطلاعات خصوصی شرکت/فاکتور در این گزارش عمومی قرار ندارد.

## نتیجهٔ بررسی فقط‌خواندنی

- ۱۲ سند حسابداری: ۸ قطعی و ۴ برگشتی. «۸ قطعی» به معنی هشت معاملهٔ مستقل نیست؛ برخی سند برگشت هستند.
- دو زنجیره کاملاً خنثی شده‌اند؛ فعال‌کردن دوبارهٔ اصل آن‌ها غلط است.
- شش رویداد مؤثر وجود دارد؛ یکی حاصل برگشتِ برگشت است. چهار مورد کنترل اولیه را گذرانده‌اند؛ دو فاکتور دارای اطلاعات الکترونیکی نیازمند بررسی مسیر منبع‌اند. مغایرت شرکت یکی از همین دو مورد با پاسخ مالک تعیین تکلیف شد.
- شمارش بالا فقط دفتر حسابداری است. فاکتورهای قدیمی بدون سند و چک‌های ثبت‌شده بدون سند حسابداری، باید در مسیر مستقل منبع تطبیق شوند.

## خروجی اجراشده

`scripts/sql/draft-conversion-inventory.sql` یک SELECT بدون تغییر اطلاعات است. `scripts/lib/draft-conversion-plan.mjs` زنجیره‌ها، تراز دقیق، حساب/تفصیلی، ارتباط منبع، شرکت و سازمان را کنترل می‌کند. نتیجهٔ آن عمداً `executable:false` است؛ کاندیدای کنترل‌شده با عملیات قابل اجرا یکی نیست.

۲۵ آزمون Node و یک آزمون یکپارچه PostgreSQL17 ایزوله موفق شدند. آزمون دیتابیس، خودِ پرس‌وجوی ذخیره‌شده را با دادهٔ مصنوعی اجرا می‌کند و ثابت می‌کند اطلاعات تغییر نکرده‌اند؛ تاریخ فارسی، مبالغ بزرگ، مغایرت شرکت/تفصیلی و سال قفل‌شده نیز بررسی شدند. آزمایش اولیه قبل از ایجاد ماژول، خطای نبود فایل بود؛ آن را بازتولید یک خطای محصول یا آزمون RED مالی محسوب نمی‌کنیم.

اجرای دوبارهٔ کنترل با فایل‌های خصوصی خارج از مخزن:

```sh
node --test scripts/draft-conversion-plan.test.mjs
node --test scripts/draft-conversion-inventory.test.mjs
node scripts/draft-conversion-preflight.mjs PRIVATE_INVENTORY.json PRIVATE_RESOLUTIONS.json
```

خروجی CLI فقط مجموع‌ها و نوع مغایرت است؛ کد خروج ۲ یعنی مغایرت باقی است. اطلاعات اصلی، مقادیر مشتری و فایل تصمیم‌های خصوصی نباید در Git قرار گیرند.

## کار باقی‌مانده

1. پشتیبانی یکسان از منبع و سند حسابداری موقتِ متصل. اکنون فاکتور فروش صرف داشتن لینک سند را قطعی تلقی می‌کند و قطعی‌سازی خرید، لینک سند موقت را نمی‌پذیرد. ساختن چنین رکوردهایی پیش از اصلاح، سندی می‌سازد که کاربر نتواند درست قطعی کند.
2. شناسهٔ عطف پایدار، شمارهٔ موقت/قطعی سمت سرور، ذخیرهٔ اتمیک منبع و سند، گزارش با انتخاب وضعیت و مسیر بررسی/قطعی‌سازی.
3. اجرای تراکنشی تبدیل با کنترل نسخهٔ داده، جلوگیری از بازنویسی توسط مرورگر قدیمی، حفظ ارتباط سابقه و آزمون برگشت عملیات. منبع در شرکت تأییدشده می‌ماند؛ اثر ثبت اشتباه در شرکت قبلی خنثی می‌شود، نه اینکه سند قبلی جابه‌جا شود.
4. پس از اجرای واقعی، تطبیق دفتر و منابع برای همهٔ شرکت‌ها و ثبت شمارش دقیق تبدیل‌ها. هیچ مرحله‌ای از این فهرست با موفقیت ابزار پیش‌بررسی، انجام‌شده محسوب نمی‌شود.
