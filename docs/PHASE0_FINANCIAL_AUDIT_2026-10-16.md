# گزارش یک‌صفحه‌ای فاز صفر — ممیزی هسته کنترلی و سند خودکار Finora
**تاریخ:** ۱۴۰۵/۰۷/۲۴ · **دامنه:** فقط «فاز ۰» پرامپت `finora-master-prompt-cloud.md`، **نه** فاز صفر نقشه‌راه هشت‌فازی قدیمی · **Baseline کد:** `612998edb51274ac1e6136a31265cd17b9abd265`. ارزیابی با مطالعه `AGENTS.md`، `README.md`، کل `PROJECT_STATE.md`، ساختار مخزن، JS عملیاتی، SQL و CI انجام شد. **بدون تغییر رفتار/اسکیما/داده مالی.**

## خلاصه واقعی
- موتور سند دوبل **وجود دارد**: `js/journal-engine.js` سند draft/posted/reversed، تعادل دوبل، ابعاد، منبع و شش پروفایل اصلی `sale/purchase/receipt/payment/expense/income` را در مرورگر مدیریت می‌کند. فروش/خرید/دریافت/پرداخت/هزینه/درآمد به آن وصل‌اند؛ صورت‌وضعیت، تنخواه، حقوق، ذخایر، تعدیل انبار و استهلاک نیز **در برخی عملیات** خطوط سند می‌سازند. جزئیات و ۲۳ ردیف رویداد در [EVENT_COVERAGE.md](EVENT_COVERAGE.md) ثبت شده است.
- **پوشش کامل نیست:** چک مستقل فقط در datastore ثبت می‌شود؛ سند اختصاصی چرخه چک، برگشتی مستقل فروش/خرید، COGS فروش، تحصیل دارایی، تسعیر ارز، تسویه VAT و اختتامیه/افتتاحیه خودکار مشاهده نشد. بعضی اعمال مثل حقوق/استهلاک/صورت‌وضعیت نیاز به کلیک جدا برای قطعی‌سازی دارند. «خودکار» در کد کنونی عمدتاً **کلاینتی** است.
- **مسیرهای دستی/نیمه‌دستی:** `jeSaveManual/jePostUi/jeReverseUi` و `jeCreateDraft/jePost/jeReverse/jeAutoPost/jePostLegacySource` شناسایی و در فایل پوشش فهرست شدند.
- **کنترل سرور فعلی محدود است:** داده دفترکل در `public.records(collection,id,data JSONB)` نگهداری می‌شود؛ `finora_sync_records` از کلاینت upsert می‌گیرد. تریگرهای قفل posted برای UPDATE/DELETE موجودند، اما محافظ INSERT زیر سند قطعی در SQL دیده نشد؛ منطق تعادل/شماره‌دهی/قفل در JS اصلی است. `ux_finora_posted_source_identity` از تکرار بعضی منبع‌ها جلوگیری می‌کند، ولی معادل RPC اتمیک جامع نیست.
- **ریسک داده خام:** `js/sync.js:139–143` تابع `neutralize` پیش از استفاده رشته‌ها `<` و `>` را تغییر می‌دهد؛ در فاز صفر به داده یا تابع دست نزدیم.
- **تست‌ها:** ۳۸ فایل Playwright، ۳۵ چک استاتیک/regex، ۱۴ اسکریپت رفتاری/ترکیبی، ۵ ابزار/کتابخانه و ۱ فایل Python شناسایی شد. اجرای واقعی baseline در GitHub **123/123 Chromium PASS**، تست‌های Golden/accounting PASS، سه DB آزمایشی PASS و Security SUCCESS بود. [TEST_AUDIT_PHASE0.md](TEST_AUDIT_PHASE0.md) شامل فهرست نام فایل‌ها و تفاوت تست رفتاری/وجود عبارت است. این شواهد **آزمون کامل Postgres هسته مالیِ فاز ۱ نیست**.
- **تاریخچه:** نسخه کامل `PROJECT_STATE.md` (۲۹۰٬۹۱۳ کاراکتر، ۸۰۹ خط) عیناً در `docs/archive/PROJECT_STATE_PRE_MASTER_PHASE0_2026-10-16.md` بایگانی شد؛ SHA فایل مبدأ و آرشیو یکسان است. فایل اصلی به راهنمای فشرده تداوم تبدیل می‌شود.
- **اختلاف مستندات:** `README.md` هنوز `index.html` را «تک‌فایل» معرفی می‌کند درحالی‌که برنامه اکنون ۵۵ فایل JS منبع و باندل‌ساز Pages دارد. این اختلاف فقط گزارش شده؛ README یا معماری در فاز صفر تغییر نکرد.

## مرز اختیار، معیار پایان و اقدام بعد
**کار تکمیل‌شده فاز صفر:** جدول `EVENT_COVERAGE`، مسیرهای دستی، ممیزی اسامی تست‌ها و نتیجه اجرای واقعی، آرشیو بدون اتلاف تاریخچه و این گزارش؛ فقط مستندات تغییر می‌کنند. **بررسی‌نشده:** هیچ نوشتن/پاک‌سازی روی Production، تست ۱۰۰۰ رویداد تصادفی و migration سرور، تست کاربران واقعی و بازگردانی بکاپ انجام نشده است.

**دسترسی برای فاز صفر:** فقط GitHub؛ دسترسی به رمز/حساب مشتری یا دیتابیس عملیاتی لازم نبود. **برای فاز ۱** چون اسکیما و RPC/Postgres باید عوض شود، پیش از هر migration، مجوز صریح جداگانه و محیط تست مستقل/بازیابی امن لازم است. این گزارش خود مجوز فاز ۱ نیست.
